## 一、本轮新发现并修复：BUG-008（记账保存后列表不刷新）

### 现象
记账保存成功，但流水列表不出现新条目，**须冷启动 App 才出现**。

### 排查（推翻旧假设）
- 上一轮假设「`relationalStore.insert` 静默失败不落库」→ 经 `run_diag_insert_log.py` 抓 hilog + 回读列表**证伪**：列表里能读到上一轮存的 `+98.76`，且 `run_verify_bug008.py` 修复后两笔同日支出即时刷新 → **数据其实落库了**。
- 真因定位到 ArkUI `ForEach` 的 `keyGenerator`：
  - 分组 key 仅用 `dayStart.toString()`；子项/列表项 key 仅用 `id.toString()`。
  - 同一天新增/编辑流水时**外层 key 不变 → ArkUI 复用整个 `ListItemGroup` 旧节点 → 内层 `items` 的 `ForEach` 永不重建**，表现为「保存成功但列表不更新，冷启动才出现」。

### 修复（6 文件）
1. `entry/.../account/AccountPage.ets`：新增 `groupKey()`（dayStart+条数+每项签名）+ `txKey()`（id+amount+direction+category+accountId+note），`ForEach` 改用内容签名，任何增删改均触发重建。**（主修复）**
2. `entry/.../account/AccountManagePage.ets`：新增 `accKey()` 同类修复。
3. `entry/.../pages/countdown/CountdownListPage.ets`：新增 `evKey()` 同类修复。
4. `entry/.../account/AccountReportPage.ets`：`ForEach` key 并入 `item.cents`（切月份后同分类金额重建）。
5. `wearable/.../pages/WatchCountdownPage.ets`：新增 `evKey()` 同类修复。
6. `entry/.../data/repository/TransactionRepository.ets`：防御性校验 `insert` 返回值（`< =0` 抛错兜底静默失败）+ 移除上一轮调试日志。

### 自验证据
- `run_verify_bug008.py`：保存两笔同日支出（不冷启动）后立即检查 → 列表即时出现 `-amt1` 与 `-amt2`（平板 + 手机均 PASS）。
- `run_diag_insert_log.py`：决定性证据，列表出现上一轮存的 `+98.76` → 数据落库正常。
- 编译：entry + wearable 双端 `assembleHap` BUILD SUCCESSFUL。
