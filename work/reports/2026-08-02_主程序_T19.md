## 一、根因回顾（QA 已定位到行）

`HomePage.ets` 三卡文案走 `private countdownMain()/focusMain()/billMain()` 三个普通方法，build 经方法调用**间接**读取外部 `@ObservedV2` 单例 `homeVM` 的 `@Trace` 字段。ArkUI V2 下 `@Trace` 变化只精确刷新「build 中**直接读取**该属性」的 UI 节点；经 private 方法间接读取**不建立依赖** → `aboutToAppear:24` 的 `vm.load()` 若晚于首帧完成，三卡永久停在初值（`petCard` 因 `Text(this.vm.petEmoji)` 直接读取故始终正常）。QA 根因记录见 `work/docs/BUG_LIST.md` 第 14–21 行。

## 二、改动摘要（2 文件）

### 1) `entry/src/main/ets/pages/home/HomePage.ets`（主修复）
- 新增 import：`import { AppContextHolder } from '../../common/AppContextHolder';`
- `private isLg(): boolean` → `@Computed get isLg(): boolean`（同根因预防：`isLg` 经 private 方法读 `winWidthVp`，与三卡同源隐患）
- `private countdownMain()/focusMain()/billMain()` 三个方法 → `@Computed get`
  - 内部 `getContext(this).resourceManager` 改为 `const context = AppContextHolder.get() ?? getContext(this); const rm = context.resourceManager;`
  - 兜底依据：`EntryAbility` 在页面渲染前已 `AppContextHolder.set()`；`@Computed` 求值时机可能早于组件挂载，`getContext(this)` 此时不可用。兜底写法与 `MainPage.ets:96/109` 同款惯例。
- build() 内 7 处调用去括号：`this.isLg`、`this.countdownMain`、`this.focusMain`、`this.billMain`（原带 `()`）。

### 2) `entry/src/main/ets/pages/pomodoro/PomodoroStatsPage.ets`（同根因加固，QA 建议连带）
- 删除 `private maxWeekValue(): number` 与 `private barHeightPercent(idx: number): string` 两个方法（内部经私有方法读 `vm.weekDays` 的 `@Trace`）。
- 改为在 `@Builder chart()` 内**直接读取** `const weekDays = this.vm.weekDays;` 与 `const todayIdx = this.vm.todayIndex;`，就地计算 `maxVal` 与每根柱 `pct`。
- 保留 `weekDayNames()`（仅读 `getContext(this).resourceManager`，不读 vm，无依赖风险）。
- 说明：该页实际因 `chart()` 内 `Text(this.vm.weekDays[idx] …)` 已有直接读取锚定依赖、大概率自愈；此处为消除同根因脆弱写法、防后续重构回归，属**预防性加固而非确认缺陷**。
