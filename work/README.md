# 伴伴 App — Agent 集群工作区

老板使用手册（30 秒看懂）。

## 目录结构

```
work/
├── README.md            ← 本文件
├── PROJECT_BOARD.md     ← 任务看板（唯一事实源）
├── roles/               ← 6 份员工角色提示词（开新对话时贴第一条消息）
├── docs/                ← 员工产出的文档（Bug清单、SPEC草稿、陪跑手册等）
├── reports/             ← 员工交接单（日期_角色_任务.md）
└── repo/               ← （仅本地）BanBanDefense 代码快照，不入库——仓库本身就是代码
```

## 怎么用

1. **开一个新对话 = 雇一名员工**：把 `roles/` 里对应文件的全文粘贴为该对话的第一条消息，并告诉它工作区路径
2. **日常驱动**：
   - 有新目标 → 找【项目主管PM】对话说，它拆任务进看板
   - 让某员工干活 → 去它的对话说「读看板，领你的任务」
   - 想知道进展 → 找【项目秘书】对话说「汇报」
3. **编译报错** → 把 DevEco 报错原文贴给【主程序】对话
4. **信息流动**：员工之间不直接通信，全靠看板 + 交接单。员工干完活必须更新看板，这是铁律

## 员工名单

| 对话 | 角色文件 | 干什么 | 建议启用时机 |
|---|---|---|---|
| 项目主管 PM | roles/01 | 拆任务、派活、验收 | 立即 |
| 项目秘书 | roles/02 | 一页纸进展汇报 | 立即 |
| 主程序 | roles/03 | 编译消错、修 Bug、特色开发 | 立即（主力） |
| QA 测试 | roles/04 | 四端核验清单、代码走查、整包回归 | 立即（主力） |
| 上架专员 | roles/05 | AGC 陪跑手册、商店素材（8/12 前备齐） | 8 月初 |
| 产品策划 & 竞品分析 | roles/06 | 竞品分析→特色提案（8/4 签字截止）、V1.0 SPEC | **立即（本周关键）** |

## 关键排期（对所有员工生效）

- **8/14 代码冻结：所有开发+测试完成；8/15 起走华为上架流程；9/7 提审兜底**
- 特色功能决策链：竞品报告 8/1 → 提案 8/3 → 老板签字 8/4 → 开发完 8/11 → 回归完 8/14；8/4 没签字则特色顺延 V1.0
- 落后 ≥2 天就砍需求（顺序：新特色 → L-5 还款联动 → 宠物等级 → 统计热力图 → 手表端）
- `repo/docs/handover/06_AI_CONTEXT.md` 是编码约束权威源
- 已签字决策（09 文档 D-001～D-012）任何人不得重开
- 真机验证 / DevEco 编译 / AGC 后台操作只有老板本人能做
