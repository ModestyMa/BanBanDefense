## 一、根因（与工单一致）
全仓从未申请通知权限（无 `requestEnableNotification` 调用）→ 系统提醒配额 = 0 →
`ReminderService.scheduleForEvent → publishOne → reminderAgentManager.publishReminder`
在通知权限未开时抛 `"The number of reminders exceeds the limit[0]"`。
原 `saveEvent()` 中 `refreshReminders()` 未 try/catch，错误冒泡至 `onSave().catch` 显示「保存失败」；
而 `insert()/update()` 在 `refreshReminders()` **之前**已执行完毕 → 数据已入库却提示失败 →
用户重试产生重复记录（QA 实测点 3 次保存 = 3 条完全相同重复条目）。

## 二、改动（entry/src/main/ets/viewmodel/CountdownViewModel.ets，1 文件）
- 新增 `import { hilog } from '@kit.PerformanceAnalysisKit';` 与常量 `DOMAIN = 0x1102`、`TAG = 'CountdownViewModel'`；
- `saveEvent()`：将 `refreshReminders(ev)` 移出 `if(isNew)/else` 分支，统一在分支之后用 `try/catch` 包裹；
  失败时仅 `hilog.warn` 记录、不 reject、不阻断已成功的 `insert/update`；
- `insert/update/PetCardService.pushToCards().catch/load` 的执行顺序与逻辑完全不变。

```typescript
if (isNew) {
  ev.createdAt = Date.now();
  ev.reminderIds = '';
  const newId = await CountdownRepository.insert(ev);
  ev.id = newId;
} else {
  await ReminderService.cancelForEvent(ev);
  ev.reminderIds = '';
  await CountdownRepository.update(ev);
}
// 提醒调度降级为非阻断（参照 PomodoroEngine.ets:136-142 同款，BUG-006/T20）
try {
  await this.refreshReminders(ev);
} catch (err) {
  hilog.warn(DOMAIN, TAG, '提醒调度降级: %{public}s',
    err instanceof Error ? (err as Error).message : String(err));
}
```
